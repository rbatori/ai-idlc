# AI-IDLC Overview

## Definition

**AI-IDLC — AI Integration-Driven Lifecycle** is a lifecycle for engineering solutions primarily by integrating existing technologies with AI assistance.

The method assumes that valuable delivery may consist mostly of integration design, configuration, automation, infrastructure, policy and evidence. Custom code is used when necessary, but it is not the organizing center of the lifecycle.

## Fundamental unit: Intent

Every meaningful initiative starts with an **Intent**: a statement of the outcome that should exist when the work is successful.

An Intent should capture:

- desired outcome;
- problem or opportunity;
- business and technical context;
- scope and exclusions;
- constraints;
- risk;
- measurable success criteria.

The Intent is progressively refined into integration decisions, Units of Work, validation criteria and evidence.

## Lifecycle

1. **Intent** — define the outcome and boundaries.
2. **Discovery** — understand systems, constraints and current state.
3. **Integration Design** — define how tools and platforms will work together.
4. **Construction & Configuration** — implement integrations, configuration, automation, policy, infrastructure and any required code.
5. **Validation** — verify behavior, security, resilience and acceptance criteria.
6. **Delivery & Operations** — deploy, observe and operate the integrated capability.
7. **Evidence & Learning** — preserve traceability and feed lessons into future Intents.

## What makes AI-IDLC different

Traditional software lifecycles often treat source code as the primary implementation artifact. AI-IDLC does not.

The implementation of an Intent may be mostly:

- API configuration;
- identity federation;
- SaaS administration;
- infrastructure as code;
- workflow automation;
- policy definition;
- observability;
- test automation;
- operational procedures;
- evidence collection.

AI-IDLC therefore evaluates progress by **verified outcomes**, not by amount of code produced.
