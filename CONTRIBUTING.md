# Contributing to AI-IDLC

AI-IDLC is intended to evolve through real-world use and community contribution.

## Ways to contribute

You can help by:

- proposing improvements to lifecycle stages;
- refining artifact definitions and templates;
- contributing generic examples;
- reporting ambiguity or missing guidance;
- proposing governance and risk improvements;
- sharing lessons from applying AI-IDLC in real integration projects.

## Contribution principles

Contributions should:

- remain vendor-neutral unless documenting a clearly labeled example;
- preserve the integration-driven focus;
- distinguish normative guidance from optional practice;
- avoid assuming that custom code is always required;
- keep human accountability proportional to risk;
- favor verifiable outcomes and evidence;
- avoid product-specific confidential information.

## Process

1. Open an issue for substantial changes when discussion would help.
2. Fork the repository or create a branch.
3. Keep changes focused and explain the problem being solved.
4. Update documentation and examples where terminology changes.
5. Open a pull request describing the rationale and expected impact.

## Method evolution

Changes that materially alter lifecycle stages, terminology, governance gates or core principles should explain:

- motivation;
- alternatives considered;
- compatibility impact;
- migration considerations;
- supporting real-world experience when available.

## Conduct

Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
